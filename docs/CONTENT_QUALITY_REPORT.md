> 诊断时间：2026-10-30

## 一、结论摘要

**最重要的发现：系统自上线以来，联网搜索从未真正生效过。**

所有历史简报都不是"基于检索结果写的"，而是模型（Ollama qwen3:8b）凭训练记忆编出来的。这不是模型的问题，是**上游数据源断供**——searxng 的 general 引擎 100% 返回 0 条。

| 检查项 | 诊断结论 | 严重度 |
|---|---|---|
| 搜索链路 | searxng general 引擎全部失效，`results` 恒为 `[]` | **P0 致命** |
| 查询准确性 | Bing 中文长查询跑题，约 40% 主题严重偏离 | **P1 高** |
| 提示词 | 明确要求"每节要有具体数据、机构名称"，等于在无素材时逼模型编造 | **P1 高** |
| 配图质量 | 无图源筛选，混入自媒体/营销站配图 | P2 中 |
| 字数达标 | 目标 2000 字，实际 1000–1500 字 | P3 低 |

## 二、诊断方法与证据

### 2.1 P0：搜索链路完全失效

从执行数据库取出 `HTTP Request`（searxng general）节点的原始输出：

```json
{
  "query": "AI短剧漫剧",
  "results": [],
  "unresponsive_engines": [
    ["baidu",     "Suspended: CAPTCHA"],
    ["google cse","timeout"],
    ["quark",     "Suspended: CAPTCHA"],
    ["sogou",     "unexpected crash"],
    ["wikidata",  "timeout"],
    ["wikipedia", "timeout"]
  ]
}
```

**6 个引擎全部不可用**。逐个单独测试结果：

| 引擎 | 结果 | 原因 |
|---|---|---|
| baidu | 0 条 | CAPTCHA 封禁（suspended 3600s） |
| quark | 0 条 | 阿里 CAPTCHA 封禁（suspended 900s） |
| sogou | 0 条 | 代码异常 `AttributeError` |
| google cse / wikipedia / wikidata | 0 条 | 网络超时 |
| **bing / 360search** | **0 条且无任何报错** | 请求未真正发出或解析器失效 |

**关键反证**：图片搜索（`categories=images`）**完全正常**，每次稳定返回 10 条。说明网络通、searxng 服务正常，**只有 general 类别坏了**。

已尝试但未奏效的修复（均实测验证）：

1. 伪装浏览器 User-Agent → bing 仍 0 条
2. 关闭 HTTP/3（bing 引擎 `enable_http3=True`）→ 仍 0 条
3. 清空 `/var/cache/searxng` 缓存 → 仍 0 条
4. 放宽 timeout 3s → 6s → 仍 0 条

**结论**：searxng general 在当前环境下不可用，继续投入排查性价比低，改为直连方案。

### 2.2 P1：Bing 中文长查询跑题（关键且反直觉）

改用 Bing 直连后，先验证抓取可行性：

```
HTTP 200 | 619ms | 103,025 字节 | b_algo 命中 10 个  → 抓取完全正常
```

但解析出的内容**严重跑题**。实测 5 个主题：

| 主题（用户输入） | 实际召回 | 相关性 |
|---|---|---|
| 中国高铁 | 中国高速铁路、12306、国铁集团 | 5/10 ✓ |
| 低空经济eVTOL商业化路径 | 低空经济、发展指数报告 | 8/10 ✓ |
| AI短剧漫剧 | 漫剧频道、AI短剧平台 | 2/10 △ |
| **固态电池产业化与装车进度** | **SSD固态硬盘、固态硬盘价格** | **0/10 ✗** |
| **天道强势文化** | **《天道》电视剧、豆瓣** | **0/10 ✗** |

继续做对照实验，定位到规律：

| 查询词 | 召回结果 |
|---|---|
| `人形机器人产业化进展` | 人形娃娃、人形公仔、手办 ✗ |
| `固态电池 产业化` | 固态硬盘、SSD 选购指南 ✗ |
| **`人形机器人`**（纯核心词） | 人形机器人百科、22款产品介绍 ✓ **10/10** |
| **`固态电池`**（纯核心词） | 固态电池百科、2025-2028 趋势、知乎 ✓ |

**原理（大白话）**：
Bing 处理中文查询时会先做**分词**，然后把分出来的词用**宽松的 OR 逻辑**去匹配。
"固态电池 产业化"被拆成 `固态` + `电池` + `产业化`，其中 `固态` 是个高频热门词（固态硬盘），
命中量远大于完整词，于是**"固态硬盘"把真正的"固态电池"挤到了后面**。
而只搜 `固态电池` 时，没有碎片词干扰，召回就准了。

**一句话记住**：**中文搜索，宁短勿长。加修饰词反而把结果带跑偏。**

### 2.3 P1：提示词主动诱导编造

改造前的提示词原文：

```
2. 每节要有具体数据、机构/公司名称或时间点，禁止空话套话。
```

在没有素材的情况下，这条等于命令模型"必须给我编出具体数字和公司名"。
Ollama qwen3:8b 是 8B 小模型，最容易照做——于是造出"3200亿吨公里""增长187%"这类看似专业
但**完全无法溯源**的数字。

**实证**：两次不同主题（特斯拉飞行汽车 / 小鹏飞行汽车）生成的简报**几乎逐字相同**，
只有公司名被替换（连"MIT 交通实验室测算减少35%地面流量"这种细节都一字不差）。
这是典型的"模板化幻觉"——模型在无素材时套用同一个内部模板。

### 2.4 其他

| 问题 | 实测数据 |
|---|---|
| 简报结构用 `【】` 而非 Markdown | 8 次执行中 `##` 标题数均为 **0** |

## 三、已实施的修复

### 3.1 搜索源：searxng → Bing 直连

| 节点 | 改动 |
|---|---|
| `HTTP Request` | URL 改为 `https://cn.bing.com/search?q=...&setlang=zh-CN`；加浏览器 UA + `Accept-Language`；`responseFormat=text`；2 次重试 |
| `Code in JavaScript` | 重写为解析 Bing HTML，提取标题/链接/摘要 |

**技术要点**：
- Bing 的结果链接常包一层跳转壳 `https://www.bing.com/ck/a?...&u=a1<base64url>`，
  不还原会导致所有来源都指向 bing 自己 → 已实现 base64url 解码还原真实 URL。
- n8n Code 沙箱里 `new URL()` **不可用**（实测抛异常），域名统计改用正则提取。

### 3.2 多候选查询 + 相关性自动择优（核心改进）

针对 2.2 的跑题问题，实现"**先搜、再打分、不行就换词重搜**"：

```
1. 用主题原文搜一次
2. 计算「主题 2-gram」与「标题+摘要」的重叠率作为相关性得分（0~1）
3. 得分 < 0.15 判定跑题 → 自动生成候选词（切分片段 + 4/5/6/8/10 字前缀），
   按短词优先逐个重试，取得分最高的一组
4. 得分 > 0.4 提前结束，省时间
```

为什么用 2-gram 而不是单字：单字匹配区分不了「固态电池」和「固态硬盘」（都含"固态"），
2-gram 能抓住 `固态→态电→电池` 这个连续片段，区分度更高。

**实测效果**（execId 6304 / 6305）：

| 主题 | 自动选用的查询词 | 相关性得分 | 结果 |
|---|---|---|---|
| 固态电池产业化与装车进度 | **固态电池** | 0.09 → **0.27** | 从"固态硬盘"纠正为固态电池百科/趋势报告 |
| 人形机器人产业化进展与成本曲线 | **人形机器人** | → **0.29** | 优必选、OpenLoong、天链机器人等真实厂商 |

### 3.3 提示词重写

新增三条硬约束：

1. **来源标注**：每个具体数字/年份/机构名必须能在素材中找到依据，句末标 `[n]`
2. **禁止编造**：素材中没有的数据一律不许写，改用定性描述或声明"当前公开数据有限"
3. **结构改为 Markdown**：用 `## ` 二级标题（原来用 `【】`，飞书/邮件渲染差）

配图关键词也加了约束：第 1 个必须是主题核心实体，禁止"概念图""示意图"这类泛词。

**实测效果**：

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 素材条数 | 0 | 10 |
| `##` 二级标题 | 0 | 6 |
| `【】` 旧标题 | 6 | 0 |
| 来源标注 `[n]` | 0 | 19–24 处 |
| 内容特征 | 模板化、两次主题几乎相同 | 具名到真实产品（Walker-S2、青龙 Mini） |

## 四、剩余优化建议（按优先级）

### P1：配图质量筛选（建议尽快做）

现状：图源无筛选，混入了 UC 自媒体、营销站点配图。

建议加三层过滤：

1. **图源白/黑名单**
   - 黑名单：`uc.cn`、`qctt.cn`、各类营销/广告 CDN
   - 白名单优先：厂商官网、主流媒体（新华、人民、澎湃）、百科类
2. **尺寸筛选**：searxng 图片结果里有 `img_src` 与 `thumbnail_src`，
   优先取 `img_src`（原图），并检查是否带尺寸参数（如 `?w=800`），太小的丢弃
3. **相关性回填**：把简报的 `keywords` 与图片所在页面的标题做匹配，弱相关的降级

### P2：字数不达标

现状 1000–1500 字，目标 2000。

原因分析：`numPredict: 4096` 对 2000 中文字（约需 2500–3000 token）是够的，
真正瓶颈是 **qwen3:8b 的指令遵循能力**——它倾向提前收尾。

建议（按性价比排序）：

1. 提示词里加"每节写完后自查字数，不足 300 字必须补充"（实测对 8B 模型有效）
2. 提高到 `numPredict: 6144`
3. 换更大的模型（如 qwen3:14b），代价是单次耗时从 ~70s 升到 ~150s

### P3：素材多样性

现状 10 条素材全部来自单一查询词。

建议：用 2–3 个不同候选词各搜一次并合并去重（当前只在"跑题时"才换词，
正常情况只用第一个结果）。代价是耗时 +2~4s。

### P4：时效性

现状：素材里可能混入 2019 年的旧内容。

建议：在 Bing 查询里加时间限定参数，或在解析后按标题中的年份过滤，
优先保留近 2 年的内容。

## 五、运维手册

### 5.1 每次生成后如何快速核查质量

查最近一次执行的素材与简报指标：

```bash
export MSYS_NO_PATHCONV=1
docker cp _diag/q_quality.js n8nwp-n8n:/tmp/q_quality.js
docker exec n8nwp-n8n node /tmp/q_quality.js <execId>
```

重点看四列：

| 字段 | 健康值 | 不健康时的含义 |
|---|---|---|
| `relevance` | ≥ 0.15（越高越好） | < 0.15 说明素材跑题，AI 可能写偏 |
| `hitCount` | ≥ 5 | = 0 说明搜索链路又断了 |
| `searchQuery` | 通常比主题短 | 若等于主题原文，说明没触发收窄 |
| `domains` | 非空 | 为空说明链接解析出问题 |

简报侧看：

| 指标 | 健康值 |
|---|---|
| `##` 二级标题数 | = 6 |
| 来源标注 `[n]` | ≥ 12 |
| 汉字数 | ≥ 1500（目标 2000） |

### 5.2 常见问题排查

**Q：搜索又返回 0 条了？**
A：按顺序查——
1. `docker logs n8nwp-searxng-1 --tail 20`（若还在用 searxng）
2. 直接测 Bing 连通性：`docker exec n8nwp-n8n node -e "fetch('https://cn.bing.com/search?q=test').then(r=>console.log(r.status))"`
3. 若 Bing 也挂了，检查容器出口网络

**Q：简报内容又跑题了？**
A：看 `relevance` 分数。若 < 0.15，说明候选重搜也没救回来，
此时简报会带"素材相关性很低"的提示——这种情况属于**上游检索能力上限**，
建议换个更具体的主题词重新提问（比如把"天道强势文化"改成"天道 强势文化 商业应用"）。

**Q：相关性阈值 0.15 想调整？**
A：改 `Code in JavaScript` 里的 `LOW_RELEVANCE` 常量。
调高 → 更严格，重搜更频繁（耗时↑，质量↑）；
调低 → 更宽松（耗时↓，可能放过跑题素材）。
